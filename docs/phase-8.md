# Phase 8 — File Viewer & Sorting

## Goal

Make every file row informative — thumbnail/icon, name, size, date — and give
each list a full set of sort orders: **Largest, Smallest, Newest, Oldest,
Name.**

Still read-only. Phase 8 changes how files are presented, not what happens
to them.

## Implemented

### File rows

`ScannedFileTile` now shows all four required fields:

| Element | Detail |
| --- | --- |
| Thumbnail / icon | Real preview for images and videos, category icon otherwise |
| Name | Single line, ellipsised, keyed `file_name_<id>` |
| Size | Bold, from `ByteFormatter`, keyed `file_size_<id>` |
| Date | Relative (`Today`, `3 days ago`), keyed `file_date_<id>` |

Tapping a row opens the details sheet, which now leads with the thumbnail and
shows type, exact size, the **absolute** modified date, and full location.

### Thumbnails

New `ThumbnailLoader.kt` on channel `com.mobilecleaner.app/thumbnails`:

- `contentResolver.loadThumbnail` on Android 10+, with the legacy
  `MediaStore.{Images,Video}.Thumbnails` APIs as a pre-Q fallback,
- decoding on a 2-thread background pool so scrolling never blocks the UI,
- results compressed to JPEG (quality 80) before crossing the channel,
- bitmaps recycled after compression,
- every failure — `IOException`, `SecurityException`, even `OutOfMemoryError` —
  resolves to `null` rather than an error,
- a `RejectedExecutionException` guard for requests arriving during teardown,
- `dispose()` from `MainActivity.onDestroy` to shut the pool down.

On the Dart side, `ThumbnailRepository` wraps the channel with a bounded
240-entry FIFO cache, keyed by URI and size, so scrolling back up never
re-decodes. `MissingPluginException` is caught, which is what keeps widget
tests and any non-Android host working.

`FileThumbnail` renders the result: a rounded image with a small play badge for
videos, a muted placeholder while loading, and a coloured category icon for
anything without a preview. `Image.memory` also gets an `errorBuilder`, so a
corrupt thumbnail degrades to the icon instead of throwing in a list.

`ScannedFile.supportsThumbnail` decides who even asks — images and videos by
category, plus anything whose MIME type starts with `image/` or `video/`, which
catches a photo that lives in Downloads.

### Sorting

`FileListSort` now has the five required orders, each with a `shortLabel` for
chips and a descriptive `label` for the header. Two entry points, one state:

- a horizontally scrollable **chip bar** under the header, so every order is
  one tap away,
- the app bar **sort menu**, now showing a radio mark against the active order.

`FileScanResult.compareFiles` owns the comparators. Every one of them falls
back to a case-insensitive name comparison, so files of equal size or with
identical timestamps keep a stable, predictable order rather than shuffling
between rebuilds.

### Dates

New `DateFormatter` centralises formatting: `format` for absolute dates
(`04 Aug 2026`) and `relative` for list rows (`Today`, `Yesterday`,
`5 days ago`, falling back to the absolute date beyond 30 days). It is
injectable via a `now` parameter, which is what makes it testable.

## Automated tests

`test/file_viewer_sorting_test.dart` (new):

- the five sort orders exist with the expected labels,
- each comparator ordered correctly against a three-file fixture,
- ties fall back to name,
- `DateFormatter` absolute and relative output, including the epoch-zero case,
- `supportsThumbnail` for images, videos, documents, and an image in Downloads,
- a row shows icon, name, size, and date,
- an image row renders a real decoded thumbnail and requests it exactly once,
- a missing thumbnail falls back to the category icon,
- the details sheet opens with the absolute date,
- all five chips render, default is Largest,
- **one test per sort order** asserting the list actually reorders,
- the app bar menu offers the same five orders and reorders too,
- sorting survives searching.

Existing Phase 6/7 tests were given a `_NoThumbnails` override so they stay
hermetic now that rows reach for a platform channel.

Run with `flutter test`.

## Device acceptance test

1. Open **Files → Images**. Rows should show real photo thumbnails, correct
   names, sizes, and dates.
2. Scroll fast. Thumbnails should fill in without stutter, and scrolling back
   up should be instant (cache hit).
3. Open **Videos** and confirm thumbnails carry the play badge.
4. Open **Documents** and confirm coloured category icons, not blank squares.
5. Tap each sort chip and confirm the order changes and the header label
   updates. Check Largest and Smallest are exact opposites, likewise
   Newest and Oldest.
6. Tap a row and confirm the sheet shows type, size, absolute date, and path.

## Notes and limits

- Thumbnails are generated by MediaStore, so a file the system has not indexed
  yet shows its category icon until the next media scan.
- The cache is in-memory only and is dropped when the app is killed; it is
  bounded at 240 entries to keep memory flat on huge libraries.
- Relative dates switch to absolute after 30 days rather than showing
  "11 months ago", which reads poorly for cleanup decisions.
- Sorting happens in Dart over the already-scanned list, so changing sort never
  triggers a rescan.

## Next phase hooks

Rows are now visually rich enough to support selection, so a later phase can
add checkboxes and a delete action on top of `ScannedFileTile` without
restructuring the list.
